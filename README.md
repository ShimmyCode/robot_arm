## まず、3つの課題を区別する

| 課題 | 入力 | 求めるもの | 実装 |
|---|---|---|---|
| Exercise 1：順幾何 | 関節角 q | 手先の位置と向き M | fMw / init_wMe |
| Exercise 2：微分運動学 | 手先を動かしたい速度 | 各関節の速度 qdot | fJw / control.cpp |
| Exercise 3：逆幾何 | 到達したい手先の位置と向き Md | 各関節の目標角 qf | inverseGeometry |

「姿勢」という言葉は、ここでは位置と向きの両方を含む。q は6つの関節角、qdot はその変化率。C++ の `q[0]` は数式の q1、`q[5]` は q6 に対応する。角度は rad、長さは m。

MDH 表はリポジトリの `dh_example.yml`。第4行の a は、URDF の寸法に一致する **0.035 m** とする。0.35 m ではない。

```
A_i = Tx(a_i) Rx(alpha_i) Tz(r_i) Rz(theta_i)
fMw = A1 A2 A3 A4 A5 A6
wMe = Tz(0.158)
fMe = fMw wMe
```

f は基準座標系 base_link、w は MDH の第6座標系（手首中心）、e は tool0。この MDH の w は URDF link_6 と原点は同じだが軸が異なる。今回の逆幾何も MDH に統一したので、別の軸の式を混ぜる必要はない。

## Exercise 2 — 「この速度で動くには、各関節をどれだけ回すか」

### 1. ヤコビ行列とは

関節角を少し変えたときに手先がどちらへどれだけ動くかをまとめた行列がヤコビ行列。

\[
{}^f v_e = J_e(q)\dot q,
\qquad
v=\begin{bmatrix}v_x&v_y&v_z&\omega_x&\omega_y&\omega_z\end{bmatrix}^T.
\]

上3成分は並進速度 m/s、下3成分は角速度 rad/s。角速度はロール・ピッチ・ヨー角の時間微分そのものではない。

J の第i列は「第i関節だけを 1 rad/s で回した場合」の速度を表す。最初にこの意味を説明すると、6×6 の行列でも理解しやすい。

### 2. MDH 表から Jw を自動生成する

Exercise 1 と同じコマンドを使う。

```bash
# パッケージのルート。必要な Python 依存が入った環境で実行
python3 src/python/dh_code.py dh_example.yml
# ROS パッケージをビルド済みなら PDF の記載どおりでもよい
ros2 run ecn_manip dh_code.py dh_example.yml
```

`Generated Jacobian code` の部分が手首中心の `fJw()`。今回の `robot_kr16.cpp` は、その出力を入れたもの。YAML を変えたら再生成し、C++ へ反映して再ビルドする。スクリプトが勝手に C++ ファイルを更新するわけではない。

生成の背景にある回転関節の式は

\[
J_{w,i}=\begin{bmatrix}a_i\times(p_w-o_i)\\a_i\end{bmatrix}.
\]

- a_i：基準座標系で表した関節軸の単位ベクトル
- o_i：その軸上の関節原点
- p_w：手首中心の位置
- 外積：軸から離れた点が、回転によって動く向きと速さ

球面手首の第4〜6関節は手首中心を通る。そのため **Jw の上3行の第4〜6列はゼロ**になる。ただし工具先端には長さがあるため、Je の同じ部分までゼロとは限らない。

### 3. Jw と Je の違い：工具先端までの距離

手首を回すと、そこから0.158 m離れた工具先端も動く。手首から工具先端へのベクトルを基準座標系で r とすると

\[
v_e=v_w+\omega\times r,
\quad
J_e=\begin{bmatrix}I&-[r]_\times\\0&I\end{bmatrix}J_w.
\]

`[r]_x` は外積を行列にしたもの。既存の `Robot::fJe()` がこの処理をしてくれるので、control.cpp では `fJw()` ではなく **`fJe()`** を使う。

### 4. GUI とヤコビ行列の「座標軸」をそろえる

GUI の指令は工具座標系 e、Je の出力は基準座標系 f。例えば「工具の前方」と「床に固定したx方向」は、工具の向きによって違う。

同じ工具原点の速度を、別の座標軸で表し直すだけなので

\[
{}^fv_e=\begin{bmatrix}R_{fe}&0\\0&R_{fe}\end{bmatrix}{}^ev_e.
\]

並進速度だけでなく、角速度も回転する。ここでは原点を移動しないので、この座標変換にさらに並進成分を加えない。工具の長さはすでに Je に含まれている。

例：全関節角が0のとき、工具座標のx軸は基準座標の-z軸、工具y軸は基準+y軸、工具z軸は基準+x軸を向く。工具z方向の速度指令は、基準x方向へ変換される。ただしこの例は座標変換の説明であり、ゼロ姿勢で任意の速度を実現できるという意味ではない。

### 5. 関節速度を求める

\[
\boxed{\dot q=J_e^+\operatorname{diag}(R_{fe},R_{fe}){}^ev_e}
\]

`+` は足し算ではなく、擬似逆行列を表す。

```cpp
v = robot->guiVelocityScrew();
vpMatrix rotation(6, 6); // 初期値は0
const auto R = M.getRotationMatrix();
putAt(rotation, R, 0, 0);
putAt(rotation, R, 3, 3);
vCommand = robot->fJe(q).pseudoInverse() * (rotation * v);
robot->setJointVelocity(vCommand);
```

`putAt` は指定した場所へ小さい行列を埋め込む関数。最初の R は並進速度用、2個目の R は角速度用。

正則なら普通の逆行列と同じ働きになる。特異点では実現できない速度方向があり、擬似逆は最小二乗・最小ノルムの解を返す。「特異点でもどんな速度でも実現できる」とは説明しないこと。特異点近傍では大きい関節速度が必要になることがあり、既存の `setJointVelocity()` は上限に応じて全関節速度を同じ割合で下げる。

### 先生への説明例（約1分）

> MDH 表から生成したヤコビ行列は、関節速度と手首中心の速度の関係を表します。今回は工具先端を動かすので、工具オフセットを考慮する既存の fJe を使いました。GUI の速度は工具座標系なので、並進と回転の両方を手先の回転行列で基準座標系へ変換します。その速度にヤコビ行列の擬似逆を掛けて、6関節の速度指令を求めました。

## Exercise 3 — 「この位置と向きへ届く関節角を求める」

### 1. なぜ「位置」と「向き」を分けられるのか

KR16 は第4〜6関節の軸が一点で交わる球面手首を持つ。第4〜6関節を回しても手首中心は移動しない。

したがって、

1. q1〜q3 で **手首中心の位置**を合わせる。
2. その後、q4〜q6 で **手先の向き**を合わせる。

という順序で解ける。工具先端の位置をそのまま最初の3関節だけで合わせるのではない。

PDF の生成スクリプトは順幾何とヤコビ行列を生成する。**逆幾何は自分で導出する**というのが、この課題の違い。

### 2. 工具を取り除いた目標を作る

\[
{}^fM_{w,d}=M_d({}^wM_e)^{-1}.
\]

```cpp
const auto target = Md * wMe.inverse();
const auto t = target.getTranslationVector();
```

目標工具姿勢 Md から、工具の0.158 mの長さを逆向きに戻して、手首中心の目標を得る。回転行列も含めた同次変換を使えば、工具がどちらを向いていても正しく取り除ける。

以下、この手首中心の座標を (x,y,z) とする。

### 3. q1：上から見て肩の向きを決める

\[
q_1=\operatorname{atan2}(-y,x),\quad
\operatorname{atan2}(-y,x)+\pi.
\]

`atan2(y,x)` は象限を含めて角度を求める。ここで y の前が負なのは、MDH 表の第1関節が **-q1** だから。

2個目の解は肩を反対側へ向ける分岐。腕の折れ方によっては手首が肩の後ろ側にあるため、一つに決めつけず両方を調べる。

肩の向きごとに、腕が動く鉛直平面内の座標を

\[
u=\cos q_1\,x-\sin q_1\,y-0.26,
\qquad v=0.675-z
\]

と定義する。u は肩のオフセットを除いた水平距離、v は肩から下向きに測る高さ。

### 4. q2・q3：平面内の三角形を解く

第4行には0.035 mの横オフセットがあるので、前腕を次の長さと角度でまとめる。

\[
L=\sqrt{0.67^2+0.035^2},\quad
\beta=\operatorname{atan2}(0.035,0.67),\quad
\phi=q_3+\beta.
\]

生成された位置式を整理すると

\[
\begin{aligned}
u&=0.68\cos q_2+L\cos(q_2+\phi),\\
v&=0.68\sin q_2+L\sin(q_2+\phi).
\end{aligned}
\]

これは長さ0.68とLの2本のリンクが作る三角形。余弦定理から

\[
c=\frac{u^2+v^2-0.68^2-L^2}{2(0.68)L},\qquad
\phi=\pm\arccos(c).
\]

\[
\boxed{q_2=\operatorname{atan2}(v,u)
-\operatorname{atan2}(L\sin\phi,0.68+L\cos\phi)},
\qquad
\boxed{q_3=\phi-\beta}.
\]

最初の atan2 は肩から目標への方向、2個目は上腕とその方向のなす角。両者の差で上腕の角度が分かる。±は肘の2分岐。

| 計算結果 | 意味 |
|---|---|
| -1 ≤ c ≤ 1 | 三角形が作れる |
| c > 1 | その肩分岐では遠すぎる |
| c < -1 | その肩分岐では近すぎる |

計算誤差だけの僅かなはみ出しは `clamp` で補正するが、大きくはみ出す場合は解を作らない。

### 5. q4〜q6：MDH の手首姿勢を分解する

最初の3関節が作る回転は

\[
R_{03}=R_z(-q_1)R_x(\pi/2)R_z(-q_2-q_3-\pi/2).
\]

目標からこの回転を取り除けば、手首が作るべき回転になる。

\[
R_{36}=R_{03}^{T}R_{fw,d}.
\]

転置で逆回転になるのは回転行列の性質。**この R03 は今回の MDH 座標系の式**であり、URDF link_3 の軸の式と混ぜないこと。

一方、表の第4〜6行から

\[
R_{36}=R_x(-\pi/2)R_z(-q_4)R_x(\pi/2)
R_z(-q_5)R_x(-\pi/2)R_z(-q_6).
\]

この積を展開すると、角度を取り出すのに必要な要素は次の5個になる。添字は **C++ と同じ0始まり**。

\[
\begin{aligned}
R_{02}&=\cos q_4\sin q_5,& R_{22}&=\sin q_4\sin q_5,\\
R_{12}&=\cos q_5,\\
R_{10}&=-\sin q_5\cos q_6,& R_{11}&=-\sin q_5\sin q_6.
\end{aligned}
\]

よって

\[
\begin{aligned}
s&=\pm\sqrt{R_{02}^2+R_{22}^2},\\
q_5&=\operatorname{atan2}(s,R_{12}),\\
q_4&=\operatorname{atan2}(R_{22}/s,R_{02}/s),\\
q_6&=\operatorname{atan2}(-R_{11}/s,-R_{10}/s).
\end{aligned}
\]

±で手首の2分岐を調べる。MDH 表には -q4 などが現れるが、その負号と固定の90度回転は上の行列展開に織り込み済み。

### 6. 特異姿勢・複数解・到達不能への対応

**手首がまっすぐ（q5=0）**だと、上の式では s=0 になり、割り算できない。このときq4とq6は個別には決まらず、その和だけが決まる。

\[
S=q_4+q_6=\operatorname{atan2}(R_{01},R_{00})+2\pi k.
\]

現在角 q0 にできるだけ近くするには

\[
q_4=\frac{q_{0,4}+S-q_{0,6}}2,\quad q_6=S-q_4
\]

とし、関節制限を満たす範囲へ補正する。q5=pi は第5関節の制限±130度の外なので採用しない。

肩2分岐×肘2分岐×手首2分岐で、通常は最大8個の幾何学的な解がある。さらに第4・6関節などは±180度を超えて動けるため、同じ向きを表す±360度の角度も調べる。

```cpp
addCandidate(candidate, Md); // 関節制限と、順幾何が目標に合うかを確認
return bestCandidate(q0);    // 現在角との差の二乗和が最小の候補を選択
```

候補のない目標では現在角を返して保持する。手首中心が第1軸上にある特異位置では、位置だけでq1を決定できないため、実装は現在のq1から候補を作る。この特殊な連続解全体の探索までは行っていない。

### 7. control.cpp での使い方

```cpp
qf = robot->inverseGeometry(Md, q);
robot->setJointPosition(qf);
```

q は現在の関節角、Md は目標姿勢。逆幾何で求めたqfを位置指令として送る。Exercise 3では工具の経路を直線にする必要はない。目標の**位置と向き**へ到達することを確認する。

### 先生への説明例（約1分）

> KR16 は球面手首なので、位置と向きを分けて逆幾何を解きました。最初に目標工具姿勢から工具オフセットを取り除き、手首中心を求めます。q1 は水平面の方向から、q2 と q3 は腕の平面内の三角形を余弦定理で解いて求めました。その後、最初の3関節の回転を目標回転から取り除き、MDH の第4〜6行を展開した行列の要素から q4、q5、q6 を求めました。複数解は関節制限と順幾何で確認し、現在角に最も近いものを選びました。

## よく聞かれる質問

| 質問 | 答える内容 |
|---|---|
| なぜ逆行列でなく擬似逆？ | 特異点で通常の逆行列が存在しない場合も扱うため。実現不能な速度まで実現できるわけではない。 |
| なぜ回転行列を2つ使う？ | 並進速度と角速度の両方を工具軸から基準軸へ変換するため。 |
| Jw と Je は同じ？ | 手首中心と工具先端は別の点。回転時に工具の長さによる並進速度が生じる。 |
| なぜ工具オフセットを逆に掛ける？ | 最初の3関節で決められる手首中心の位置に戻すため。 |
| なぜ±の解を両方調べる？ | 同じ工具姿勢へ届く、肘や手首の異なる配置があるため。 |
| 近い解とは？ | 各関節角の現在値との差の二乗和が小さい解。選択候補内で比較する。 |
| 逆幾何も自動生成した？ | いいえ。生成したのは順幾何とヤコビ行列。逆幾何は球面手首の性質から解析的に導出した。 |
